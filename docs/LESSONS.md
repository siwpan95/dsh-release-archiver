# LESSONS · 踩坑台账

> 每条都由实跑触发、附日期与现象。新增坑请追加在本文件末尾，不删旧条（旧坑会以新形态复发）。
> 来源：本仓 2026-10-29 / 10-30 / 11-02 三次归档实跑 + 技能 `github-release-source-archive-download` 的 SKILL.md。

## 1. 校验不能在目标盘上做（2026-10 首次踩）

**现象**：对 `D:` / `G:` 上的归档直接跑 `tar -tzf` / `unzip -t`，完好文件被判「损坏」，
于是重下、再判损坏，陷入无效返工。
**根因**：目标盘（外置/网络盘、exFAT）与 Git Bash 的流式读取配合不稳定，`tar` 逐条读时偶发短读。
**处置**：**一律 `cp` 到临时目录再校验**（`${TMPDIR:-/tmp}`）。`dl_one.sh` 与 `verify_tag.sh` 都已内置。

## 2. 并行下载会 fork 失败（2026-10 首次踩）

**现象**：同时起多个后台下载任务，报 `fork: Permission denied`（CreateProcessW errno 13），
整个脚本连同重试链一起死。
**处置**：**串行**。一个 tag 的 zip 与 tar.gz 顺序跑；多个 tag 逐个跑。
`archive_one.sh` 单进程顺序执行两格式，正是为绕开这条。

## 3. `tar` 不认 `C:/...`（2026-10-30 踩）

**现象**：`tar -tzf "C:/Users/.../x.tar.gz"` 报 `Cannot connect to C: resolve failed` —— 它把 `C:` 当远程主机。
**处置**：Git Bash 下用 `/c/...` 形式；脚本内不要拼接盘符路径，统一走 POSIX 形式。
注意 `cp` / `unzip` **接受** `C:/...`，只有 `tar` 有这个坑 —— 所以「同一个路径换个工具就报错」不代表文件坏了。

## 4. `unzip` 的 `symlink error: File exists` 是良性（2026-10-29 起连续三次）

**现象**：解压源码包时 stderr 出现 `symlink error: File exists`，容易被判成失败。
**事实（2026-11-03 修订）**：「链接本身已正确建立」只在当时的机器上成立 —— 换到 `@SIWPAN` 机
（无 symlink 权限）实测 **14 条链接全部未建立**，stderr 照样只有良性的 `symlink error`，
硬指标合计条目差 14 ⇒ FAIL。**stderr 良性 ≠ 解压无缺失**，两件事必须分开判。
**判据**：不看 stderr，只看 `verify_tag.sh` 的硬指标；根治见第 12 条（解压改走 tar.gz）。

## 5. 代理镜像会截断大文件（技能已记录）

**现象**：`ghproxy.net` 等镜像对 >15 MB（尤其 >40 MB）的文件中途断开，`curl: (18) transfer closed`，
且**均不支持 HTTP Range**（`-C -` 报 33），无法续传。
**处置**：`codeload.github.com` **直连优先**，镜像只作兜底。实测直连速度可接受
（2026-11-02 两个文件共 ~80 MB，下载 + 校验 + 解压 1.6 万文件全程约 2 分钟）。

## 6. `rm` 清理临时文件会挂起（技能已记录）

**现象**：safe-bin trash shim 下 `rm` / `rm -f` 可能长时间不返回，重试链卡死。
**处置**：每次尝试用**唯一临时文件名**（含 `$$` 与 attempt 序号），残留留在临时目录，**不删**。

## 7. release 名 ≠ tag（技能已记录）

**现象**：release 的 `name` 是 `v0.2.0-rc.2`，而 `tag_name` 是 `dsh-v0.2.0-rc.2`；用错前缀查 API 直接 404。
**处置**：一律以 `tag_name` 为准；本地文件名也以 tag 命名，否则差集永远对不上。

## 8. 「无新增」与「API 失败」必须分开（2026-11-02 加固）

**现象**：若 `curl` 失败但脚本继续跑，`grep` 得到 0 条 tag，差集为空 ⇒ 会被误报成「无新增」。
**处置**：`check_new.sh` 在 `curl` 非 0 或解析出 0 条 tag 时 **exit 3 并打印原因**，
绝不把「查不到」当成「没有」。

## 9. 解压目录幂等，但判据不幂等（2026-11-02 记录）

已解压的目录不会被重复解压（避免覆盖），但**复核每次都跑全量 `find`**：
1.6 万文件约 1 分钟量级，可接受；不要为了「快一点」改成抽样 —— 漏解压正是抽样查不出来的。

## 10. `${TMPDIR:-/tmp}` 是**假保险**（2026-11-02 本仓首次自测即踩）

**现象**：`verify_tag.sh` 首次实跑直接判 `tar.gz 完整性校验不通过`，而同一份文件用 `/tmp` 手验是好的。
**根因**：Windows 上 `TMPDIR` **本身就是盘符形式**（`C:\Users\<user>\AppData\Local\Temp`），
`${TMPDIR:-/tmp}` 的语义是「**未设置**时才用 `/tmp`」 ⇒ 变量已设置，永远退不到 `/tmp`，
拿到 `C:\...` 喂给 `tar` ⇒ 立刻复现第 3 条的 `Cannot connect to C: resolve failed`。
**讽刺之处**：第 1 条纪律是「在临时目录副本上校验」，而这里**临时目录本身不可用**，
于是纪律执行了、判据却假失败 —— 若不先做负向自测，这条会被当成「归档坏了」而误重下 45 MB。
**处置**：`scripts/lib.sh` 的 `tmp_root()` 统一解析：有 `cygpath` 就转 POSIX（`/c/...`），
否则退 `/tmp`；全部脚本（含 `dl_one.sh`）只认这一个入口。**教训：默认值写法要区分「未设置」与「设成了不可用的值」**，
前者 `:-` 够用，后者必须先归一化。

> **补记（2026-11-02 当晚）**：`dl_one.sh` 是从技能**逐字复制**来的，第一次统一时被漏掉，
> 直到做「不存在的 tag」负向用例才暴露：`DLDIR="${TMPDIR:-/tmp}/_ghd"` 拼出
> `C:\Users\…\Temp/_ghd/...`，`mkdir -p` 与 `curl -o` 双双失败，日志里只有一行
> `No such file or directory`，**看起来像下载失败，其实是临时目录没落地**。
> ⇒ **复制来的脚本最容易漏统一**：凡批量改路径解析，必须用 `grep -rn 'TMPDIR\|/tmp' scripts/` 全量搜一遍，不能只改自己写的那几个。


## 11. Gitee raw 的 302 会把「一致」判成「不一致」（2026-11-02 建远端后核对时踩）

**现象**：匿名核对远端文件时，`README.md` / `scripts/verify_tag.sh` / `docs/LESSONS.md` 三个 blob 哈希**全不匹配**；
而同一提交的匿名浅克隆工作区与本地 blob **完全一致** —— 「远端内容错了」与「克隆是对的」自相矛盾。

**根因**：`https://gitee.com/<owner>/<repo>/raw/<ref>/<path>` 返回 **302** 跳 `raw.giteeusercontent.com`；
`curl` 不加 `-L` 时 body 是 **411 字节的跳转 HTML**，喂给 `git hash-object` 当然得到另一个哈希。

**旁证**：该 302 响应头 `Etag: W/"<sha>"` **就是真实 blob 哈希** —— 服务端已给出正确答案，只是 body 不是它。
快速判据还有字节数（411 vs 6816）与 `Content-Type: text/html`。

**纪律**：凡「取文件内容做校验」的链路，先证明拿到的是**内容**而非跳转页（`curl -sL` + 校验字节数/类型）。
**别把传输层现象当成数据层事实** —— 这与第 6 条（CDN 滞后）是同一类错误的两个面。

## 12. 复核 FAIL 先找「哪一步少物化了条目」—— 判据对，环节错（2026-11-03 根治）

**现象**：`@SIWPAN` 机首跑，10 个 tag 全部 `条目数不符: 文件 N + 链接 0 = N ≠ zip 条目 N+14`，
差值恒为 unzip stderr 里 symlink error 的条数（14）。
**根因**：解压用的是 **zip + Info-ZIP `unzip`** —— 它在 Windows 上对符号链接条目**无法物化**
（每条报 `symlink error: File exists` 后静默跳过）⇒ 解压树**必然缺 N 个条目**。
`@DESKTOP-KQABATS` 机此前 PASS 纯属其环境恰好能建链 —— **同一个脚本，跨机行为分裂**；
提权 / 豁免都只是把环境问题转嫁给下一台机器。
**根治（v1.2.0）**：解压改走 **tar.gz**（`tar -xzf`）。实测同一 tag：
`tar` 在无提权机器上 exit 0，14 条符号链接全部物化为真链（运行时建不出真链时按约定退化为内容拷贝），
`文件 16058 + 链接 14 == zip 条目 16072` 恒成立 —— **判据一行没改，换了解压环节**。
zip 仍下载、仍做完整性校验、仍充当条目数基准清单，只是不再用它解压。
**方法论**：硬指标 FAIL 时，别急着怀疑判据或环境，先把链路拆开问「每个条目在哪一步被物化」——
**判据对而环节错**，改判据（豁免）是放大坑，改环节才是根治。
